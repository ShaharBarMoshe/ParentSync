Governance · identity · data

Controls a bank would recognise, built because the output is acted on

Human in the loop

Nothing reaches the calendar unapproved. The PENDING row is the durable record — the notification is only a view onto it, so dismissing it decides nothing and a restart loses nothing.

Auditable suppression

Layers 3 and 4 run after the write and mark the row REJECTED. A suppressed duplicate is a row you can audit, not an absence you cannot — and the dedup counters reconcile against the table.

Identity

OAuth 2.0 with PKCE, CSRF state, refresh tokens encrypted at rest, and a separate client per purpose — a shared client was a latent race that only the real library exposed.

Data boundary

Everything local. Tracing is opt-in, and the docs state exactly what leaves the machine when you turn it on. Backups exclude the message database outright.

An alert never travels over the channel that is broken. WhatsApp failures are reported by email; Google failures are reported over WhatsApp. It sounds obvious written down — it was not obvious when the only alerting path was the thing that had just died.

Connection state reports real health, not the mere presence of a token

Four controls, then the one I am proudest of. Human in the loop: the durable record is a database row, not a UI state. That is what makes it survive a crash, and it is why I could not use LangGraph's interrupt. Auditable suppression is the one I would push in a banking interview. When the system decides not to act, that decision is itself a row — status REJECTED, with the reason and the counter that reconciles against it. Compare that to a pipeline where a suppressed item simply never appears: you cannot audit an absence. Identity is ordinary OAuth done properly, with one detail worth telling: the per-purpose client came from a real race that only showed up against the actual googleapis library. Mocking the library hid it. So the test uses the real one. The amber box is the lesson I would hand someone on day one. For a while, the only way the system told me WhatsApp was broken was a WhatsApp message. Now the alert routes out over a different channel than the one that failed. Obvious in hindsight; it took an outage.
