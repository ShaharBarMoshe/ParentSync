Incident · the one I would tell you about unprompted

The app read its own output and fed itself

The mobile client alerts you when messages are waiting but no API key is configured. That alert is itself a notification — and the client reads notifications.

So it ingested its own alert as a message. Which raised the count. Which re-posted the alert. One real message became 100 rows.

With a key configured, every one of those would have been a paid model call on the app's own text.

Why it was dangerous

Nothing crashed. No error, no alert, no failing test. It would have surfaced as a bill.

How I found it

Dumping actual state on an emulator rather than trusting that a green test run meant a healthy system.

The fix

Drop anything on the app's own channels — checked before the source test and deliberately not configurable. A watch list is the user's business; reading our own output never is.

The generalisation I took from it: an agentic system that both emits and consumes needs an explicit identity boundary, or it will eventually consume itself. That failure is silent, and in a metered system it is expensive.
