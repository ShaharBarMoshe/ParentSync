The premise

Reading school WhatsApp groups is the feature. Being wrong in public is the engineering problem.

What it does

Watches parent groups and teacher email, extracts the real events — trips, deadlines, appointments — and syncs them to the family Google Calendar.

Why it is hard

Hebrew and English, forwarded flyers, cancellations, truncated messages. The model is confidently wrong often enough that correctness has to be designed, not hoped for.

The stake

A wrong event is not a bad answer in a chat window. It is a parent at the wrong school gate on a Sunday morning.

That stake is why this looks like a banking problem. Every control below exists because the output is acted on, not merely read: approve before publish, an audit row for every suppression, and a failure mode chosen deliberately for each stage.

In daily use since v1.0 · ~1,165 automated tests across four suites

I want to land one idea here: the difficulty is not getting a model to read Hebrew. It is that the output is acted on. If a chatbot is wrong, a human reads it and shrugs. If this is wrong, an event lands on a calendar two parents coordinate around and nobody re-reads the source message. That is the same property that makes a bank nervous — output that becomes an action. Everything after this slide is a control that exists because of that.
