Failure modes

Every layer fails open — because the two mistakes are not equal.

A duplicate card is an annoyance. A silently dropped event is a missed school trip.

5 / 13

Short slide, big idea. This is the one I would want remembered. Every one of those dedup layers fails open. If the embedding call times out, if the judge runs out of quota, if the calendar lookup throws — the event goes through to the approval queue as though nothing had matched. That was a decision, not an accident, and it is written in the code comments so the next person does not "fix" it into failing closed. The reasoning is the asymmetry. A duplicate the parent has to dismiss costs them two seconds. An event silently suppressed by a transient model failure is a missed school trip, with nothing in the interface to show it ever existed. Those are not equal costs, so the failure mode should not be symmetric either. And the deterministic collapse exists precisely because the layer next to it can fail open — it is the floor underneath the part that can go missing. If they push: yes, in a payments context the asymmetry inverts and you fail closed. The skill is knowing which direction, per stage, and writing down why.
