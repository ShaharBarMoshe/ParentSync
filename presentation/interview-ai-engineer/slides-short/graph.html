Eight nodes. Three conditional edges, each one skipping money.

Keep this to about a minute; the next slide is the interesting one. The pipeline is: load messages, dedup, extract, persist, screen, request approval, process dismissals, sync. Eight nodes. The three conditional edges are all about not spending money: One — if every message group turned out to be a duplicate, skip extraction and persistence entirely and jump to the sync step. Two — if the model quota is exhausted mid-pass, leave the messages unparsed for the next run rather than writing "no events found" over them. That second part was a real bug: a swallowed quota error used to mark messages parsed-with-no-events, which lost them permanently. Three — if approval is switched off, skip the screening stage, because screening itself costs an LLM call and an embedding call per event. It only earns those calls when a human will actually be asked to approve something.
