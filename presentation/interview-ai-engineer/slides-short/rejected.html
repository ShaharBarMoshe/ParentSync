interrupt() · the checkpointer · a tool loop

3 / 13

This is the slide I most want to be asked about. Spend time here. interrupt() first, because human-in-the-loop is textbook LangGraph and I did not use it. Resume re-runs the node from the top. By the time a human answers, that node has already written to the database and already sent the approval card. A resume would send every card a second time. So the PENDING database row is the interrupt — and unlike an in-memory thread, it survives the process dying, which for an approval a parent might answer tomorrow morning is the whole requirement. The checkpointer: unparsed rows are already a durable work queue. A crash is recovered by the next pass reading the same rows. A checkpointer would cost memory per thread for recovery I already have. A tool loop: the pipeline is fixed. A loop adds non-determinism to a path that writes to a family's calendar. I will happily argue where a tool loop does belong — read-only, bounded, with a hard call ceiling — but not on the write path. The general point: knowing which framework features not to use is worth more than knowing all of them.
