LLM-as-a-judge

A model judging a model — with a deterministic floor underneath it.

Instrumented, fail-open, and last in the order because it is the most expensive.

7 / 13

A real LLM-as-a-judge in production, not a benchmark exercise. It is its own port — one question only: do these two events describe the same gathering? It runs against same-slot and same-day siblings for that child. Three things I would stress, because they are what make a judge usable rather than decorative. It is treated as fallible. It fails open, and the deterministic collapse runs in front of it so the judge only ever sees genuinely ambiguous pairs — the "same gathering at two times" case never reaches it. It is instrumented. Every firing increments a counter, so I can tell you the judge's rate rather than assume it. And it is last, because it is the only layer that costs a call per sibling. An event landing on a busy day costs several. If there is time, the structured-output point is worth adding: Gemini rejects parts of JSON Schema at call time, not build time. You can write a schema that is valid, type-checks, passes every mocked test, and is refused in production. So the test runs the real conversion — mocking it would hide the exact failure the test exists for.
